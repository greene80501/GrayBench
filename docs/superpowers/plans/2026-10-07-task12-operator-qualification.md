# Task12 Operator Qualification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Qualify the explicit complete-operator condition without hidden numeric or storage obligations, and obtain independent admission before using it in a headline cohort.

**Architecture:** Keep the pinned native condition historical and preserve the source-bound explicit value condition as a separate recipe. Validate its mathematical oracle and actual isolated transport separately. Bind evidence to exact engine, task, runtime image and resource conditions; never infer runtime qualification from host controls.

**Tech Stack:** Locked Python 3.12, Qiskit 2.4.2, NumPy, protected value protocol 3, immutable OCI image digests, ledger-backed control evidence.

**Spec:** [Explicit operator contract and design](../../reliability-evidence/task12-explicit-operator.md).

## Current implementation and limits

This qualification plan was recorded after the local implementation and review,
not presented as a pre-implementation specification. The first prototype used
graph transport; review demonstrated hidden storage restrictions. The final
logical-value contract removes those restrictions. A second review demonstrated
phase-anchor bias, now covered by a failing-before/passing-after unitary regression
and an explicit symmetric overlap rule. Finite local controls do not establish
general oracle correctness or encoder integrity. Runtime and human admission
remain pending. Docker availability was not confirmed by the user's “Continue”.

## Global constraints

- Do not rewrite original task bytes, old controls, scores or evidence bindings.
- Do not silently accept arbitrary extended-precision, object or subclass arrays;
  those require a separately specified contract and support review.
- Use one public condition per suite for every selected provider. Freeze the
  revision before generation; do not change prompts after inspecting model answers.
- Keep unsupported representations distinct from incorrect numeric answers and
  preserve scheduled denominators.
- Do not launch Docker or native builds until their existing external blockers
  are resolved. Do not remove sockets, bypass Windows Application Control or
  start paid model generations as a substitute for oracle qualification.
- Keep Actions disabled through `[skip ci]` commits. Keep the PR draft and
  `release_eligible=false` until required qualification is actually established.

## Files and verification boundaries

`engine/src/graybench/task12_revision.py` owns the exact ancestor binding, public
contract and independent checker. `evaluation_recipes.py` registers explicit
selection and restoration. `engine/tests/test_task12_revision.py` checks source
binding, campaign reconstruction, provider preparation, hostile types, numeric
edges, codec round trips and the gated isolated roster.

`docs/reliability-evidence/task12_controls.py` declares the 56 semantic controls
before isolated execution. `task12_local_verification.py` writes a source-bound
host plan before execution and exactly recreates its finite observations and
calibrations. The source-bound artifact bundle must distinguish local, isolated
and independently admitted evidence.
