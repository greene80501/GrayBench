# Campaign verdict consistency

The trusted-stdout capture inspector previously checked authored oracle-review logs, but the live campaign runner and ledger did not apply those checks to model results. A synthetic returned judgment with a claimed `pass` and a captured trusted `fail` was scored as a pass. Direct ledger recording and a consistently rehashed row/event rewrite also accepted that contradiction. Seven regression tests reproduced the missing checks before implementation; they used synthetic trusted messages and saved answer fixtures, without model calls or Docker execution.

The [campaign evidence validator](../../engine/src/graybench/judgment_evidence.py) now checks the returned generation digest, complete frozen task and judge maps, dataset/judge/runtime identities, the selected task's judge digest and its manifest. Reported completion hashes, including nested wrapper and candidate-execution metadata, are compared with the stored `Generation.text`. New-policy pass/fail records require a completion binding. Declared bounded trusted-stdout captures are validated through nested wrappers using the same byte/outcome checks as oracle-review inspection. A scored native pass/fail requires its parsed worker result and must match that result's status. Its retained file fingerprint and size must also match the pinned worker's exact JSON serialization, including ASCII-escaped Unicode details. Native worker messages remain same-process observations; this does not fix the native track's candidate/test tampering risk.

Protected value judge manifests now freeze ordered case IDs as well as the private-case digest. A scored verdict requires nonempty case results with strict Boolean `passed` values, the complete declared order, no duplicate IDs, and an aggregate consistent with all cases. The semantic judge and candidate value runner both retain the completion digest. These fields bind captured metadata; they do not attest that the submitted values came from native Qiskit objects or independently establish the semantic oracle's quality.

All three planning builders freeze `judgment_evidence_policy="cohort-bound-v1"` before execution. The extension participates in protocol identity and comparison compatibility. A declared-policy judgment cannot omit all evidence and fall back to the older bare-record form. Historical protocols omit the absent extension, preserving their serialized identities. Older bare judgments remain readable under their historical development condition; reports label them `legacy_unbound` and include a publication blocker. A historical record claiming campaign bindings or trusted captures must pass those consistency checks rather than using a missing policy to evade them. Older records that never captured completion hashes or a case-ID roster cannot retroactively claim those new-policy guarantees.

Both live judgment runners validate results before recording a scored verdict. An inconsistent returned result becomes `infrastructure_error`, leaves the run unscored, and preserves the rejected result's outcome, judge digest and evidence as diagnostics. A thrown host exception also stays unscored. The durable judgment claim remains in place; restarting does not rerun that sample to obtain a better verdict. Direct ledger writes repeat the validation before committing. Ledger verification and summaries recheck the same bindings from saved blobs, so merely changing row/event hashes cannot turn the captured fail into a scored pass. A judgment cannot be written without a returned generation.

The summary adds `judgment_evidence_policy` and counts of `bound` and `legacy_unbound` judgments. These fields describe local metadata consistency. They do not authenticate an author, prove actual execution, establish oracle adequacy, or certify the result for ranking. A holder able to replace an entire unsigned ledger can still fabricate a fully consistent history; independent anchoring, task admission, runtime qualification and external reproduction remain required. Protected value tasks retain their host semantic oracle; the new policy does not invent a trusted-stdout capture where none is declared.

The comparison and missing-claim unit fixtures were updated to supply explicitly synthetic valid evidence so those tests still reach their intended branches. Follow-up review reproduced five additional failures covering different-completion evidence, rewritten native status with the original file fingerprint, and missing/empty/failed protected case evidence; they were fixed and retested. Positive and mutation regressions also cover ordered/missing/duplicate/reordered/non-Boolean protected cases, Unicode native serialization, and nested completion metadata. No production verifier was bypassed, historical artifact bytes changed, provider request changed or model answer regenerated for this increment. Existing historical scores have not been silently rescored.

October 7 verification used the locked Python 3.12.14/Qiskit 2.4.2 environment with the pinned cache enabled and `GRAYBENCH_TEST_IMAGE` unset. The final full engine suite completed with **1,412 passed, 283 skipped, zero failures** in 182.19 seconds, with 12 Windows temporary-directory cleanup warnings. The source digest was `8fb3bd8bdedfaee19ffce0b8c3e5d17a69c83060eaf63d51974500544811f519`. The follow-up implementation reviewer independently reproduced 103 focused passes and 15 skips and found no remaining blockers in the revised increment. This review is not independent task admission or proof of container execution. Docker-dependent integration remains pending.
